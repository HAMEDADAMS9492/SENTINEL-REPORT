# SentinelReport — dépendances (Python 3.10+)
#
# Installation :
#   python -m venv .venv
#   .venv\Scripts\activate        (Windows)   |   source .venv/bin/activate  (Linux/macOS)
#   pip install -r requirements.txt
#
# Note GPU : par défaut pip installe la version CPU de PyTorch (suffisante pour
# yolov8n.pt). Pour CUDA, installer torch depuis https://pytorch.org avant ce fichier.
#
# Note numpy : la borne haute « <2.1.0 » a été retirée. Elle rendait le fichier
# ININSTALLABLE sur Python 3.13+ : aucune version de numpy < 2.1 ne publie de
# roue (wheel) pour ces interpréteurs, pip retombait donc sur une compilation
# depuis les sources qui échoue (« metadata-generation-failed ») et interrompait
# l'installation de TOUT le fichier. Cette borne visait des incompatibilités de
# 2024 entre numpy 2.x, OpenCV et PyTorch, aujourd'hui résolues.
#
# Note lap : dépendance NON déclarée par Ultralytics, qu'il télécharge et
# installe TOUT SEUL au premier appel de `model.track()` (« AutoUpdate »). Sur
# un poste sans réseau, ou en pleine analyse vidéo, c'est exactement le
# comportement que ce projet refuse — d'où sa déclaration explicite ici, au même
# titre que les poids récupérés par `download_models.py`.
#
# Note supervision : la dépendance a été RETIRÉE. Elle n'était plus utilisée
# nulle part : `zones.py` teste l'appartenance aux polygones avec
# `cv2.pointPolygonTest` (même algorithme du lancer de rayon, sans les ~30 Mo
# de PyAV), et la seule fonction qui l'importait — `detection.to_supervision()` —
# n'avait aucun appelant, tests compris. Déclarer une dépendance « au cas où »
# fait payer son coût d'installation sans rien rendre en échange.
#
# Note OpenCV : « opencv-python-headless » a été remplacé par « opencv-python ».
# Ultralytics dépend lui-même de opencv-python ; déclarer la variante headless
# en plus installait DEUX distributions fournissant le même module `cv2`, ce qui
# est une source classique de pannes difficiles à diagnostiquer.
